## Comment 1
**File**: `lib/resolver/template-source.ts` (file-level)
**Body**: In `findFromImport`, the `export { default as X } from './...'` path drops the component name when recursing (`findFromDecl(next, ..., null, null)`). This prevents `readGts` from disambiguating multi-`<template>` target files by name, so default re-exports can fail to resolve even though `componentName` is known at the consumer. Keep passing the original `componentName` (or otherwise provide a hint) when following default re-exports so multi-template files remain resolvable.
**Status**: AGREE — fixed in d0879e6 (propagate barrel-side `componentName` into `findFromDecl`; RESOLVED)

## Comment 2
**File**: `lib/glint.ts` (file-level)
**Body**: `findTemplateSource` intentionally bypasses its cache when `declRange` or `componentName` are provided. This call site always passes `componentName` (and usually `declRange`), which means repeated invocations of the same component will re-read and re-parse its template source during a single extraction run. Consider only passing `componentName` when it's needed for multi-template disambiguation (e.g. try a cached `declFile`-only lookup first, then fall back to a name/range-bearing lookup if the file turns out to be multi-template), or extend the cache key to include these hints.
**Status**: AGREE — fixed in d0879e6 (cache key now folds in `componentName` + `declRange`; RESOLVED)
